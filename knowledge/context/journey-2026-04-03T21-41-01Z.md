## Narrative

We started this pass because the app no longer felt dependable. Runs were stalling, the UI felt overstuffed, and the system was showing too much of its own machinery in the default experience.

The first useful diagnosis was that the app was not “slow” in a theoretical sense. It was doing too much repeated work:

- rapid polling
- thread hydration
- result hydration
- event loading
- row-detail loading for every row

At the same time, the visible product story had drifted. The main UI was carrying:

- product state
- debug trace
- tool ledger
- reward metrics
- raw payloads

The fix for this iteration was to stop negotiating with the overload and split the experience cleanly:

- restrained product workspace by default
- separate debug workspace for engineers
- lazy row detail loading
- compact polling for active runs
- lineage carried on rows to support better entity/document reasoning

This pass did not finish the deeper runtime simplification. It did establish a cleaner baseline to refactor from tomorrow.

## Tricks And Workarounds Used

- Keep the heavy trace data, but move it to a separate route instead of deleting observability.
- Use grouped trace presentation rather than raw append-only event dumping.
- Add light document-vs-entity rejection heuristics in ranking as a temporary guardrail.
- Humanize criterion labels during normalization so product UI does not leak backend IR.
